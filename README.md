# Калькулятор рейтингу

Сайт читає вибрані Excel-файли у браузері та створює результат на комп'ютері
користувача. Файли не надсилаються на сервер, не записуються в localStorage,
IndexedDB чи cookies. Завантажені результати залишаються у папці завантажень.

## Робота над сайтом у VS Code

Цей репозиторій — основний проєкт сайту. Відкрийте папку `web_rating` у VS Code
через **File → Open Folder**. Редагуйте файли безпосередньо тут:
`index.html` — калькулятор, `faq.html` — довідка, `styles.css` — оформлення,
`app.js` та `rating-core.js` — обробка файлів і розрахунок.

Після змін відкрийте **Source Control** (`Ctrl+Shift+G`), перегляньте різницю,
додайте потрібні файли до коміту кнопкою **+**, введіть повідомлення й натисніть
**Commit**. Потім виконайте **Push** або **Sync Changes**, щоб передати коміт
на GitHub. Локальний коміт сам по собі не надсилає зміни на сервер.

ZIP і ручне завантаження файлів через сайт GitHub для цього процесу не потрібні.
Робочі Excel та результати обчислень залишайте поза репозиторієм;
їхні формати також виключені через `.gitignore`.

## Локальний запуск без інтернету

Відкрийте `index.html` у Chrome або Edge. Усі ресурси лежать у корені
репозиторію, зокрема `exceljs-4.4.0.min.js` і `rating-core.js`.
Додаткових установлень немає. FAQ відкривається через посилання на сайті.

## Розрахунок та необов’язкові перегляди

Посилання **FAQ** праворуч угорі відкриває `faq.html` в окремій вкладці, щоб
зберегти вибрані файли та результат у калькуляторі. У довідці є вимоги до
файлів, пояснення розрахунку, переглядів, помилок, експорту та приватності.
Довідка працює без JavaScript і публікується разом із калькулятором.

1. Оберіть `statistics.xlsx` та `rating.xlsx` і потрібний лист «Рейтинг фінал».
2. За бажанням додайте третій Excel із переглядами. Назва файлу довільна.
3. Лише якщо додали третій файл, перевірте місяць і рік. Вони визначаються з формули годин поза рейтингом
   обраного листа. Якщо формул із датами немає, місяць потрібно вказати вручну.
4. Натисніть «Розрахувати». Перевірте попередження і завантажте Excel.

Третій файл не потрібен для запуску. Без нього поле місяця переглядів
вимкнене та не перевіряється. Великий `rating.xlsx` може читатися певний час:
кнопка показує стан завантаження. Помилковий доданий файл переглядів можна
прибрати й одразу повернутися до розрахунку з двома файлами.

Шукається лист `Пересмотры` / `Перегляди`, а не перший лист книги. Потрібні
колонки: `ПІБ консьерж`, `Дата замовлення`, `Решение`,
`Количество добавленных баллов` (підтримуються українські назви та повний
заголовок дати з приміткою про 5 днів).

Враховуються лише записи з рішенням «да» / «так» / «yes», числовими додатковими
балами та **датою замовлення** у вибраному місяці й році. Дата відправлення
форми не використовується. Кілька погоджених рядків одного працівника сумуються.
Рядки файлу вважаються окремими записами; не додавайте дублікати одного рішення.
Сума замінює «перегляд» у рейтингу, а не додається до вже внесеної суми. Коли
врахованих записів немає, буде 0 і попередження. Без третього файлу попередні
перегляди зберігаються. Кнопка «Прибрати перегляди» повертає цей режим.

ПІБ зіставляються без урахування регістру, зайвих пробілів і варіанта апострофа.
Для скороченого ПІБ використовується зіставлений ПІБ зі статистики КЯ або
однозначний збіг прізвища / імені. Неоднозначні та незнайдені ПІБ у переглядах
не отримують балів навмання: записи показуються в журналі. Перевіряйте його,
особливо коли в рейтингу є лише прізвища.

Якщо ПІБ відрізняються, після розрахунку з’являється блок ручного зіставлення.
Оберіть відповідного працівника лише якщо впевнені, що це одна людина, і
натисніть «Розрахувати» ще раз. Вибір фіксується у журналі експорту, не
зберігається на сервері й скидається при зміні файлів, листа чи місяця.
Записи з невідомою датою звітуються за всім файлом: віднести їх до місяця
неможливо, тому вони не враховуються.

Таблиця на сайті й перший лист експорту містять усі 14 колонок з прикладу
рейтингу в початковому порядку, а також додаткові підписані колонки джерела,
місце та статус. КК заповнюється оцінкою КЯ зі статистики. Заголовки й ПІБ
закріплено; широку таблицю можна прокручувати. Перегляди й фінал показуються
до трьох знаків, бали на годину — у відсотках, як у джерелі.

Фінал = **КК в рейтингу + РЗ в рейтингу + рейтингу** (M + K + I).
РЗ та «РЗ в рейтингу» завжди дорівнюють **0**, навіть якщо у вихідному файлі
є старі оцінки РЗ: актуальний рівень знань береться з іншого джерела й у цей
калькулятор не імпортується. Інші внески не збільшуються: КК × 0,4 та
ефективність × 0,4. Наприклад, КК 90 та ефективність 100 дадуть 36 + 0 + 40 = 76.

Перераховуються години в рейтингу, бали на годину, ефективність та внесок КЯ.
База ефективності береться з формули
джерела: підтримується MAX одного діапазону колонки «бали на годину» або
числове значення. Зберігається саме група вихідних рядків MAX, навіть після
сортування результату; сірі працівники, які не рейтингуються, виключаються
з цієї групи. Довільні формули Excel сайт не виконує; невідоме
правило нормування викликає помилку, а не довільну заміну формули.

Без КЯ результат попередній: внесок КЯ дорівнює 0. За відсутності балів або
непозитивних годин фінал і місце не визначаються, рядок сірий. Якщо такий рядок
бере участь у рейтингу та входить у базову групу MAX, розрахунок зупиняється. П’ять основних зон —
10 / 20 / 40 / 20 / 10%; однакові бали мають однакове місце й зону, тому
для малої команди та нічиїх відсотки приблизні.

**Сіре позначення у вихідному фінальному листі означає «не рейтингується».**
Працівник залишається внизу таблиці, без місця й участі в розподілі зон,
навіть із високим фінальним балом. Бали та перегляди збережено довідково,
а рядок виключено з групи MAX. Це стосується, зокрема, новачків і людей із
менш ніж ⅓ місячної норми годин. Саму норму сайт не вгадує: орієнтир —
сірий колір у джерелі. Якщо всі рядки сірі, таблиця доступна без місць та
фінальних балів, для яких немає бази учасників.

Сірий статус визначається за заливкою клітинки ПІБ, з урахуванням пріоритетів
умовного форматування. Підтримуються суцільні сірі RGB-заливки, сірі кольори
стандартної індексованої палітри та кольори теми з відтінком. Для умовного
форматування підтримуються прості порівняння з числом, текстом або посиланням
на клітинку, правила джерела на кшталт `$O:$O=57`, TRUE/FALSE, `cellIs` з
одним порівнянням і перевірка порожніх клітинок. Використовуються значення
вихідного листа до сортування. Сіра окрема числова клітинка не виключає
працівника. Невідоме правило, яке може вплинути на сірий статус, або відсутній
кеш потрібної формули зупиняє розрахунок із поясненням.

У завантаженому Excel є легенда, а з третім файлом — журнал переглядів і лист
«Зміни переглядів» із сумами до / після. Журнал не копіює ID клієнтів,
посилання на діалоги чи текст звернень. Результат містить розраховані значення,
не живі формули: для оновлення повторіть розрахунок на сайті. Вхідні Excel
не змінюються. Результат завантажується як Excel-книга.

## Публікація на GitHub Pages

Файли сайту вже розташовані в корені репозиторію. Для публікації з гілки
`main` джерело GitHub Pages має бути налаштоване як **Settings → Pages →
Deploy from a branch → main → / (root)**. За такого налаштування після
відправлення коміту в `main` GitHub Pages публікує оновлену версію сайту.

Якщо Pages уже налаштовано таким чином, повторювати налаштування не потрібно.
Стан публікації перевіряйте у вкладці **Actions** репозиторію. Після завершення
відкрийте сайт та перевірте зміни; якщо браузер показує стару версію, виконайте
повне оновлення сторінки (`Ctrl+F5`).

До публікації входять тільки код, локальна бібліотека та документація. Не
завантажуйте всю робочу папку «рейтинг»: Excel, результати, знімки таблиць та
інші робочі дані не повинні потрапляти на хостинг чи в історію репозиторію.
`.gitignore` допомагає при роботі через Git, але не захищає ручне завантаження
файлів через сайт GitHub.

## Що захищено

- ExcelJS 4.4.0 постачається локально; CDN і Google Fonts не використовуються.
- Контрольна сума SHA-256 бібліотеки перевіряється під час збирання архіву.
- Політика CSP в HTML забороняє fetch, XHR, WebSocket, beacon і надсилання форм.
  Зовнішні скрипти, картинки, фрейми та вбудований JavaScript теж заборонені.
- Значення з Excel відображаються як текст, а не виконуються як HTML.
- Немає аналітики, облікових записів, серверної обробки та сховища результатів.

Відкритий сайт та його код бачать усі, хто має посилання. Це не дає їм доступу
до файлів іншого користувача чи результатів у його вкладці. Це також не є
входом «тільки для працівників»: обмеження доступу потребує окремого рішення.

Хостинг отримує запити сторінки та її ресурсів і може зберігати IP-адресу та
інші технічні журнали. Це не вміст Excel. HTTPS захищає передавання сторінки,
але не захищає від зміни коду тим, хто контролює публікацію. Використовуйте
двофакторний захист GitHub-акаунта та обмежте доступ на зміну репозиторію.

CSP зменшує ризик, але не є гарантією від усіх витоків: зміна самого сайту,
розширення браузера чи скомпрометований комп'ютер залишаються окремими ризиками.
Для роботи зовсім без звернень до хостингу використовуйте розпаковану локальну
копію з вимкненим інтернетом.

## Оновлення

Редагуйте файли в цьому репозиторії, перевірте сайт локально, зробіть коміт і
відправте його на GitHub. Для HTML, CSS та JavaScript окреме збирання не потрібне.
Після зміни CSS або JavaScript оновлюйте параметр версії `?v=…` у відповідних
посиланнях HTML, щоб браузер отримав актуальні ресурси.

Якщо оновлюється ExcelJS, перевірте бібліотеку та оновіть контрольну суму
і відомості нижче.

Перевірка сірих рядків: `python tests/check_gray_rows.py` (потрібні Python,
`selenium`, `openpyxl` та Chrome). Тест створює тимчасові вигадані дані й
перевіряє заливки, умовне форматування, місця, зони та експорт. Для незалежної
звірки з локальною робочою книгою можна додати `--rating "шлях/до/rating.xlsx"`.
Книга не копіюється в репозиторій; ПІБ у результатах тесту не виводяться.
